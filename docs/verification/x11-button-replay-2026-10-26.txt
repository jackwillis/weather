xweather interrupted button gestures: #55 / audit F2

A held Location OK survived Escape, so a later release could save cancelled
edits after the dialog closed. Holding OK and accepting with Return could also
apply twice, and a right-button release could activate a left-button press.

Clear the pressed state on Location Escape and on keyboard acceptance. A new
left-button press resets the old gesture. Ignore releases from other buttons,
and only activate a control while its owning mode is still active. Add a guard
to apply_location so a closed dialog cannot apply its fields.

xdrive now supports separate down/up edges, sharing the existing click sender.
The GUI scenario tests: edit + heldOK + Escape + release leaves config unchanged
and does not fetch; wrong-button release does not save/fetch; Return with heldOK
applies once; release outside does nothing; an ordinary OK click still applies.

Red evidence: the original application saved cancelled edits and fetched twice
where one fetch was expected; the Return case reached five fetches rather than
two (including earlier replayed actions). Seven new checks failed. Log:
/tmp/weather-buttons-red.log.

Scope: F2 only. F1 (dialog/fetch input scheduling) and F3 (Unicode input) remain
open under #55. Related scheduling/search changes already exist in draft #17
and must be preserved at integration. No core parser input path was added.
