Package transfer and OS 9 delivery status: remaining #57 / G1 script findings

Package orchestration now checks each producer and consumer separately using
files instead of POSIX shell pipelines with hidden producer status. Build
metadata readelf/gcc and file-size collection failures propagate. A completed
local stage.tar is uploaded to a private, validated remote directory, then
extracted with a checked status before pkg_create is invoked. A downloaded
package remains .part until tar validates it; only then is it renamed to the
published .tgz. Success removes own local/remote staging. Failures leave remote
staging for diagnosis; no unrelated /tmp/wxpkg tree is removed. Cross-tool
prefix is configurable with WEATHER_CROSS_PREFIX, defaulting to the existing
Linux cross-toolchain path. No compilation or installation runs on maul.

Delivery now clears a stale success marker on invocation, checks attachment,
mount/info/source/copy/detach, and only publishes deliver.done after success.
APPL is copied with ditto -rsrc into a private destination-volume staging dir,
then renamed after successful detach, preserving the old app on copy failure.
Exit cleanup attempts detach when a device was reported and cleans own staging.
Defaults stay weather-dev and /tmp/deliver.{log,done}; isolated test overrides
WEATHER_DELIVER_DEST and WEATHER_DELIVER_STATE avoid real OS 9 volumes. Disk
commands and resource-fork behavior are not hardware-verified while Tiger is
parked. Later failures after publication (for example final marker rename)
can leave the new application installed without a success marker.
