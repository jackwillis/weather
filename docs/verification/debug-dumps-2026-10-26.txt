Complete debug dumps: issue #53 / audit C7

The old core dump stopped at 1500 bytes, then sent that buffer through a logger
whose formatted-record limit is 512 bytes. The header therefore overstated what
the user actually received, while the tail of longer responses disappeared.

Emit the true byte count, followed by numbered records containing at most 240
input bytes each. Bytes outside printable ASCII (including CR/LF/tab) become
'.', so each record is one physical line. Offsets refer to the original bytes.
The payload plus the internal request/response label and size_t decimal offset
fits both existing 512-byte platform loggers. Stack use drops from 1600 to 241
bytes; no allocation or platform logging API changes are needed. Existing
LogDebug filtering is preserved; dump size is bounded by request/response limits.

Regression
The real CLI contacts the local MET fixture, with fixture-only contact metadata,
and test/debug_dump.py reconstructs the entire sanitized HTTP response. It checks
the exact total byte count, contiguous offsets, maximum record size and every
response byte against the fixture, including the tail beyond byte 1500.
Against the old implementation: feature tests106 passed1failed; failure output:

FAIL: complete debug response
