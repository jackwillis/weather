Automatic refresh resume: issue #51 / audit F6

Scope
Preserve the pending automatic refresh/retry deadline when the user disables or
re-enables automatic updates. An overdue deadline becomes due on the next model
tick. Fresh data retains its remaining interval. Failure retries retain their
backoff, and toggling during an active fetch does not queue another fetch.
The existing timestamp argument remains accepted for callers; changing the
option itself no longer needs the current time. Clock rollback clamping remains
in tick().

Red evidence
The updated host unit suite against the old model produced 528 checks, 5 failed.
Failures covered fresh countdown extension, overdue refresh suppression and
failure retry postponement. See /tmp/weather-refresh-red.log.

Limit
This is the scheduling part of #51. Validation of provider observation timestamps
against the current time remains outstanding. No timestamp age threshold is
introduced here.

Host verification

and Makefile flag checks passed. Final run /tmp/weather-refresh-check.log.
make check-san: AddressSanitizer explicitly enabled alongside UBSan; 537 unit

Additional model regressions cover cancellation after failure, manual refresh
