# Weather 0.0.1 (pre-release)

A deliberately rough pre-release, published to prove the release pipeline (packaging, artifacts, tag, draft
release). It promises nothing: no support, and Mac OS 9 needs manual setup. The real gate is v0.1 (issue #45).

## What is in it
* `weather-0.0.1.tgz`: NetBSD/macppc binary package, installable with `pkg_add` (`weather`, `xweather`, man pages).
* Mac OS 9 app image (`.dsk`): the `Weather` window app, with the third-party notice inside.
* Source tarball `weather-0.0.1.tar.gz` and `SHA512SUMS`.

## What works
* `weather`: current conditions over certificate-verified TLS from Open-Meteo and MET Norway; retry, fallback.
* `xweather`: CDE-look X11 window with a Location dialog and automatic refresh.
* Mac OS 9 `Weather`: native window, Location dialog and persistent Preferences, manual and automatic refresh.

## Known issues
* Mac OS 9 refuses TLS until a seed is provisioned from a Linux machine (`docs/OS9-SEEDS.md`). Removing this is
  planned for v0.1 (#120).
* `xweather` has not been reviewed on maul's real X display (#70).
* One location, current conditions only.
* Open-Meteo works out of the box; MET Norway needs `contact` in the configuration.
* Nothing has been tested on hardware other than maul (Power Mac G4).
* Provider attribution and terms (#73) and the Retro68 runtime notice (#65, PR #93) must be settled before publishing.

Re-check each item against `main` before publishing.
