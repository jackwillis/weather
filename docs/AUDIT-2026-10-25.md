# Audit, 2026-10-25

Read-only audit of `main` at b5d76c4. No source or test changes accompany this document; the proposed tests at the end are
waiting for the owner's approval.

## Scope, method, limits

Four reviewers each took one layer: `src/core`; `src/tls` + `src/platform/posix` + `src/cli` + `tools/`; `src/app` + `src/ui/xweather`;
`src/platform/os9` + seed handling. Each walked the layer's boundaries (input wrong, missing, late or reordered, partially completed),
ran experiments where it could, and mapped failure modes to existing tests. The test-suite assessment and the subtraction candidates
use the `is-it-tested`, `requisite-variety` and `subtraction-audit` lenses.

Every finding carries its provenance: **[proved]** a reviewer ran something that showed it, **[read]** from reading only,
**[sim]** simulated (32-bit arithmetic on a 64-bit host). I re-checked six claims myself: I re-ran dropped-connection retry, CR-only config,
`-Sc FILE` and `-V` with a bad config; I re-read the OS 9 exit-handler order and the OS 9 provenance comment. A separate fact-checker then
reproduced most other rows marked proved and corrected this document; it could not reproduce C3, D3 and E3 (they need a TLS server, a
harness, or the network), so those rest on the original reviewer's run.

What was not covered: everything that needs hardware or X11 (no GUI run, no OS 9, no PowerPC); `make check-maul`; Linux; live
servers (no network traffic was generated); BearSSL internals; the MET Norway symbol list, which two findings quote from memory.
"Hardware-verified" in the docs means Classic under Mac OS X Tiger on the G4 (STATUS.md), not native OS 9; findings below keep that
distinction.

## Summary

The parsers are in good shape: bounds-safe, no byte-order dependence, no invariant violations in 2M random TextEdit operations (reviewer harness) or in the fuzzer's keystroke streams, 186k mutated
inputs (the sanitizer build is how `make check-san` runs them), and the TLS verification path rejects wrong-host, expired, not-yet-valid, untrusted-root and non-CA-intermediate
certificates when exercised directly.

The weaknesses are in what the program claims to the user and in what the tests are able to notice:

1. It can present old or wrong data as current (clock stepping back; stale marker cut off the status line; unmapped MET symbols; labels
   taken from the request instead of the response).
2. A few commands act on the wrong thing silently (`-Sc FILE` rewrites `~/.weatherrc`; a CR-only config loads as the Madison default).
3. Nothing in the repo's offline tests exercises certificate verification, and the fuzzer judges parsed output almost only by a
   temperature range.

## What the tests do and do not guard

**Failure space (D)**, by boundary: bytes from two remote JSON APIs; HTTP framing; TLS handshake and certificate chain; system clock;
entropy and seed state (OS 9); the config file and `-S` rewrite; the command line; keystrokes and X events; the Model's timers and state;
the build host. **Essential variables (E):** the displayed weather is correct and honestly dated; a forged server cannot get its answer
accepted; no command writes where the user did not point it. **Acceptable range (η):** no wrong value shown as correct.

**Regulator (R)**: 461 unit checks, 186,018 mutated inputs, 78 CLI scenarios, 21 GUI checks, seed and anchor tests.

What the suite does well: structural variety. It drives the parsers, TextEdit, the settings round trip, DNS lifecycle and the seed pool
through many malformed shapes, with sanitizers watching.

Where it falls short, as findings about the regulator and not only the code:

1. **Input variety is high, oracle variety is low.** The 186,018 inputs come from six seed documents and are judged by a handful of
   predicates: no crash, temperature in a plausible range, `code != kUnset`, and round-trip properties for config. Several checks
   cannot fail (`strlen(f.time) < sizeof f.time` on a zero-initialised capped array; `h.code <= 999`; the MET `code != kUnset` and time-length
   checks; `plausible_temp_t10` re-checks the parser's own predicate), and the metric-query parse results are discarded (`robust.cpp:74,81`). A wrong-but-plausible value (A4, A5, A8) passes. By Ashby's measure the suite can sense that the parser crashed, but not
   that it was wrong; adding more mutated inputs does not change that.
2. **No model of "correct weather" in the tests.** Cross-field constraints exist (humidity 0-100, wind >= 0, direction in [0,360),
   units in the response match the request, provider time near now, symbol in a known table) and none is checked. These constraints are
   the cheapest way to shrink the failure space the regulator faces; they would also be useful in the program, since A4, A5 and A7 are
   the same missing check.
3. **TLS verification has no offline test.** `tls.cpp` is not linked into `unittest`, and `make check` never sets `ONLINE`. The only
   coverage is live: `feature.sh:172` (a real fetch), `:174` and `:176` (clock seam gives "expired or not yet valid"), `:180` (empty trust set) and
   `smoke-maul.sh:15-16`; none of them runs under `make check`, and none tests host-name matching. A
   regression in the server-name, anchor or time wiring would pass `make check`. The reviewer's harness shows the code is correct today.
4. **Assertions that pass for the wrong reason.** `feature.sh` "ok metric flag" checks only the exit status (passes on A4's output);
   "hangup gives 65" locks in C2; `unittest.cpp:683` locks in A1; the OS 9 "two pools identical" check passes only because no `extra`
   is supplied, which production always does; the "1970 clock gives 71" check stops at `fetch.cpp:32` before reaching TLS;
   `feature.sh:176` depends on the live certificate being issued after 2025-01-01.
5. **The GUI scenario proves wiring, not rendering.** `fetches()` greps the log; a hung "Loading weather..." passes all 21 checks.
   Screenshots are saved but never compared. The auto-refresh timer, status-line truncation, input during fetch and key press/release
   sequences have no test. Model transitions never driven: Cancelled after Failed, `pending_reset_` with a failed fetch,
   `location_changed` while Failed, `request_refresh` while Failed, `set_auto_refresh` while Fetching or Failed, a forward clock jump.
6. **OS 9 host logic is well covered; the seams to hardware are not.** Seed parsing, rotation, ownership, DNS lifecycle (including
   wrap) are covered; the production `extra` path, the persisted successor's value, `os9_now`, `DnsBackend::notify`, TCP tick wrap and
   restart with a leftover Next or Lock are not.

On the Good Regulator point: the repository's tests are a regulator with a precise model of the *input grammar* and almost no model of
the *meaning* of a forecast. The remedy is constraints, not volume.

## Subtraction candidates

Each has evidence from grep by the reviewers; none was deleted to test it, and the suite's gaps mean "nothing breaks" would not be
conclusive anyway.

- `Model::stale()` (tests only; the UI never uses it, and the architecture doc promises stale marking): use it or delete it.
  `Model::last_error()` (no uses), `failures()`, `next_refresh_at()` (tests only), `Model::start()` (constructor only, misleading API),
  `pending_reset_` (unreachable from xweather), `LocationForm::edit_name()`, `cde::Theme::line_height` (no uses), `auto_refresh` held
  twice and synced by hand (`main.cpp:361-362`).
- Core: `openmeteo_path_buf` and `metno_path` exist only to feed one wrapper each; `MetCode.is_day = -1` duplicates `kUnset`;
  `settings_update`'s `done[16]` guard for callers that pass at most 4 keys.
- CLI: the pass-1 `-c` scan and `case 'c'` (removing them fixes B1); `main.cpp:129-130` `access()` duplicating `PosixStore.must_exist`;
  `log_set_level` (no callers); duplicate `verbose` branches at `main.cpp:133-135`; the dead EAGAIN branches; `WEATHER_NOW` and
  `WEATHER_NO_TA` once an offline TLS test exists (D2).
- OS 9 and spikes: `spike/os9/probe1.cc`, `probe2.cc` ("GUESSES from memory"), `probe3.cc`, the Probe3/Probe4 targets and the `OT_SDK`
  branch that invites Apple objects; `seed_file_probe.cc`; `spike/ta.h` (a second, unchecked trust-anchor set); unused constants in
  `ot_min.h` and the sync `OTOpenInternetServices` wrapper, against the rule that unverified calls are not added; the ten
  `WEATHER_SEED_DIAGNOSTICS` sites (three in `seed_store_os9.hpp`, seven in `seed_store_os9.cpp`) in the production seed store, which make the tested binary differ from the shipped one;
