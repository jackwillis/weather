## Mac OS 9 build (Retro68)

Draft notice for #65. Researched on 2026-10-26 from the upstream repositories (links below); this is a reading of the published
terms, **not legal advice**, and the points marked *unverified* were not checked. Jack should confirm before an OS 9 binary is distributed.

The OS 9 application is built with [Retro68](https://github.com/autc04/Retro68) (GCC 16.1 in the `ghcr.io/autc04/retro68` image). The
toolchain is not shipped with the application. What gets linked into it:

| Piece | Terms (as published upstream) | Notice to ship |
| --- | --- | --- |
| Retro68 toolchain (compiler, linker, tools) | GPL-3.0-or-later (`COPYING`). Not distributed with the app. | None for the app. |
| `libretro` runtime: startup code, console hooks, syscalls glue (`libretro/*.c`, `*.s`) | GPL-3.0-or-later **with the GCC Runtime Library Exception 3.1** (`COPYING.RUNTIME`). Upstream's README: "there are no licensing restrictions on programs compiled with Retro68". File headers read GPLv3-or-later. | Recommended: name Retro68 and the exception here. *Unverified:* that every `libretro` file's own header mentions the exception; upstream states it in the README only. |
| Multiversal Interfaces (the Mac OS headers we compile against) | MIT, Copyright 2019 Wolfgang Thaller (`autc04/multiversal`, `COPYING`). The API definitions were generated from the headers of Executor 2000, a clean-room implementation that upstream says is under a liberal licence. | MIT requires its copyright and permission notice in copies or substantial portions: include it, to be safe, in OS 9 release artifacts. |
| Import libraries `libOpenTransportLib.a`, `libOpenTptInternetLib.a` (linked so the app can call Open Transport) | Generated by Retro68's MakeImport tool from Apple's Universal Interfaces 3.4.1. Upstream's `ImportLibraries/README.txt`: they "contain the names of the exported symbols", so "I believe that no copyright restrictions apply". That is the upstream author's belief, **not a licence grant**. | Nothing to ship. **Decision for Jack:** accept that belief, or find a way to avoid linking these. |

Notes:

* Apple's Universal Interfaces are **not** used and must never be added to this repository (Retro68's README: the licence "does not allow redistribution").
* The Multiversal Interfaces do not include Open Transport. This project declares what it uses in `src/platform/os9/ot_min.h` and
  `toolbox_extra.h` (its own code) and supplies the client glue in `ot_glue.cc`; see issue #63 about the wording of the provenance comments there.
* BearSSL (above) is also linked into the OS 9 application.

Sources: https://github.com/autc04/Retro68 (`README.md`, `COPYING`, `COPYING.RUNTIME`, `ImportLibraries/README.txt`, `libretro/`),
https://github.com/autc04/multiversal (`README.md`, `COPYING`).

## Trust anchors

`src/tls/anchors.h` is generated from `src/tls/roots.pem`: the public ISRG Root X1 and X2 certificates (Internet Security
Research Group; Open-Meteo, api.weather.gov) and HARICA TLS RSA Root CA 2021 (Hellenic Academic and Research
Institutions CA; api.met.no), converted with BearSSL's `brssl ta`. Certificates are public data, not licensed software.

## Data

Forecasts come from Open-Meteo (https://open-meteo.com) and, optionally, MET Norway (https://api.met.no, Locationforecast 2.0).
Check both services' terms of use and attribution requirements before distributing widely (TODO: verify; the output already
names the source). MET Norway's terms ask every client to identify itself with a contact: this is the `contact` setting, and
the source is skipped until it is set.
